## Overview

The Bill Payment API lets aggregators pay Sri Lankan bills and top up mobile numbers from their prefunded LKR float. You create a bill payment, and CeyPay debits your float and pays the biller in LKR. Your end-user doesn't make a payment to CeyPay.

This is the same LKR float that funds your [offramps](/api/v1/offramp). CeyPay charges no fee: your float is debited exactly the bill `amount`.

Supported biller categories:

| Category | Examples |
|----------|----------|
| `MOBILE` | Prepaid mobile reloads |
| `MOBILEWALLET` | Mobile wallet top-ups |
| `FIXEDLINE` | Fixed-line telephone bills |
| `TELEVISION` | TV subscriptions |
| `UTILITIES` | Electricity, water |
| `INSURANCE` | Insurance premiums |
| `FINANCE` | Loan and finance repayments |
| `TAXI` | Taxi wallet top-ups |

## Endpoints

| Method | Endpoint | Description | Rate Limit |
|--------|----------|-------------|------------|
| GET | `/v1/bill/billers` | List billers you can pay | 300 req/min |
| POST | `/v1/bill/check` | Check an account before paying | 100 req/min |
| POST | `/v1/bill/payment` | Create a bill payment | 100 req/min |
| GET | `/v1/bill/payment` | List your bill payments | 200 req/min |
| GET | `/v1/bill/payment/:id` | Get a bill payment | 300 req/min |

<Warning>
The Bill Payment API is only available to merchants with the `AGGREGATOR` role, with bill payments enabled. Requests from accounts without access return `403`. Contact [support@ceypay.io](mailto:support@ceypay.io) to enable bill payments or top up your float.
</Warning>

## Authentication

Every endpoint requires [HMAC authentication](/api/v1/authentication) with these headers:

- `x-api-key`: Your API key ID only (for example, `ak_live_xxx`)
- `x-timestamp`: Current Unix timestamp in milliseconds
- `x-signature`: HMAC-SHA256 signature (using the derived signing key)

## How It Works

<Steps>
  <Step title="Find the biller">
    Call `GET /v1/bill/billers` and take the biller's `code`. Don't hardcode biller codes — the list can change.
  </Step>
  <Step title="Check the account (optional)">
    Call `POST /v1/bill/check` to confirm the account exists and see the account holder and amount due. For mobile reloads, pass `amount` to see which package it buys.
  </Step>
  <Step title="Create the bill payment">
    Call `POST /v1/bill/payment` with the biller code, account number, and LKR amount. CeyPay debits your float and sends the payment to the biller immediately. Store the returned `billPaymentId`.
  </Step>
  <Step title="Track the result">
    Receive a `bill.status_changed` webhook on your `webhookUrl`, or poll `GET /v1/bill/payment/:id`. If the biller fails the payment, CeyPay returns the LKR to your float.
  </Step>
</Steps>

## List Billers

Returns the billers and mobile operators you can pay, with the account format and LKR limits for each.

```
GET /v1/bill/billers
```

### Query Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `category` | string | No | Filter by category: `MOBILE`, `MOBILEWALLET`, `FIXEDLINE`, `TELEVISION`, `UTILITIES`, `INSURANCE`, `FINANCE`, `TAXI` |

### Example Request

```bash
curl "https://api.ceypay.io/v1/bill/billers?category=UTILITIES" \
  -H "x-api-key: ak_live_abc123" \
  -H "x-timestamp: 1762934400000" \
  -H "x-signature: your_signature_here"
```

### Example Response

```json
{
  "data": [
    {
      "code": "CEBB",
      "name": "Ceylon Electricity Board (CEB)",
      "category": "UTILITIES",
      "accountLabel": "Account number",
      "accountRegex": null,
      "minAmount": null,
      "maxAmount": null
    }
  ]
}
```

### Biller Fields

| Field | Type | Description |
|-------|------|-------------|
| `code` | string | Biller code — pass it as `billerCode` in other requests |
| `name` | string | Biller display name |
| `category` | string | Biller category |
| `accountLabel` | string | What to call the account field in your UI: `Mobile number` or `Account number` |
| `accountRegex` | string \| null | Pattern the account number must match, or `null` for free-form account numbers |
| `minAmount` | number \| null | Minimum payment in whole LKR, or `null` for no minimum |
| `maxAmount` | number \| null | Maximum payment in whole LKR, or `null` for no maximum |

## Check Account

Validates an account with the biller before you create a payment. Returns the account holder and the amount due or balance, where the biller supports lookups.

```
POST /v1/bill/check
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `billerCode` | string | Yes | Biller code from `GET /v1/bill/billers` |
| `accountNumber` | string | Yes | Mobile or account number (letters, digits, `/` and `-`; max 50 chars) |
| `amount` | integer | No | Mobile reloads only: amount in whole LKR, to see which package it buys |

### Example Request

```bash
curl -X POST "https://api.ceypay.io/v1/bill/check" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ak_live_abc123" \
  -H "x-timestamp: 1762934400000" \
  -H "x-signature: your_signature_here" \
  -d '{
    "billerCode": "MOBP",
    "accountNumber": "0711234567",
    "amount": 299
  }'
```

### Example Response

```json
{
  "billerCode": "MOBP",
  "billerName": "Mobitel Mobile - Prepaid",
  "accountHolderName": null,
  "balance": "0",
  "supported": true,
  "package": {
    "name": "Anytime Data 299",
    "availability": "Available",
    "dataBundle": "6GB",
    "callsBundle": null,
    "smsBundle": null,
    "validityDays": "30"
  }
}
```

### Response Fields

| Field | Type | Description |
|-------|------|-------------|
| `billerCode` | string | Biller code you sent |
| `billerName` | string \| null | Biller name |
| `accountHolderName` | string \| null | Account holder, when the biller returns it |
| `balance` | string | Amount due for bills, or the account balance the biller reports. `"0"` when unknown |
| `supported` | boolean | `false` if the biller can't serve this account — don't create a payment for it |
| `package` | object | Mobile reloads with `amount` only: what that amount buys |

<Note>
Some billers, such as TV providers, don't support account lookups. For these, CeyPay checks only the account number format and returns `supported: true` with no account holder.
</Note>

### Error Responses

| Status | Description |
|--------|-------------|
| 400 | Invalid account number for this biller |
| 404 | Unknown biller, or account not found |

## Create Bill Payment

Pays a bill or reload from your LKR float. CeyPay debits your float and sends the payment to the biller in the same request.

```
POST /v1/bill/payment
```

### Headers

| Header | Required | Description |
|--------|----------|-------------|
| `Idempotency-Key` | No | Your retry key (max 128 chars). See [Idempotency](#idempotency) |

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `billerCode` | string | Yes | Biller code from `GET /v1/bill/billers` |
| `accountNumber` | string | Yes | Mobile or account number to reload or pay (letters, digits, `/` and `-`; max 50 chars) |
| `amount` | integer | Yes | Amount in whole LKR — no cents. Must be within the biller's `minAmount` and `maxAmount` |
| `receiptMobile` | string | No | Mobile number that receives the receipt SMS (format `07XXXXXXXX`) |
| `merchantTradeNo` | string | No | Your own reference, unique per account (max 64 chars) |
| `webhookUrl` | string | No | HTTPS URL that receives `bill.status_changed` webhooks (max 2048 chars) |

<Note>
Don't send `provider`. Bills are paid from your float, so requests that include it return `400`.
</Note>

### Example Request

```bash
curl -X POST "https://api.ceypay.io/v1/bill/payment" \
  -H "Content-Type: application/json" \
  -H "x-api-key: ak_live_abc123" \
  -H "x-timestamp: 1762934400000" \
  -H "x-signature: your_signature_here" \
  -H "Idempotency-Key: bill-77120" \
  -d '{
    "billerCode": "CEBB",
    "accountNumber": "1234567890",
    "amount": 4850,
    "merchantTradeNo": "BILL-77120",
    "webhookUrl": "https://api.yourplatform.com/ceypay/bill-webhook"
  }'
```

### Example Response

```json
{
  "billPaymentId": "8a2b3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
  "merchantTradeNo": "BILL-77120",
  "status": "PROCESSING",
  "fundingSource": "AGGREGATOR_FLOAT",
  "biller": {
    "code": "CEBB",
    "name": "Ceylon Electricity Board (CEB)",
    "category": "UTILITIES"
  },
  "accountNumber": "1234567890",
  "amountLkr": 4850,
  "amountUsdt": null,
  "payProvider": null,
  "paymentNo": null,
  "reference": null,
  "refund": null,
  "paidAt": "2026-11-12T10:00:00.000Z",
  "completedAt": null,
  "createdAt": "2026-11-12T10:00:00.000Z"
}
```

### Response Fields

| Field | Type | Description |
|-------|------|-------------|
| `billPaymentId` | string (UUID) | CeyPay bill payment ID — use this to poll status |
| `merchantTradeNo` | string \| null | Your reference |
| `status` | string | Current status (see [Bill Payment Status](#bill-payment-status)) |
| `fundingSource` | string | Always `AGGREGATOR_FLOAT` |
| `biller` | object | `code`, `name`, and `category` of the biller |
| `accountNumber` | string | Account being paid |
| `amountLkr` | number | LKR amount debited from your float and paid to the biller |
| `amountUsdt` | null | Always `null` for float-funded bills |
| `payProvider` | null | Always `null` for float-funded bills |
| `paymentNo` | null | Always `null` for float-funded bills |
| `reference` | string \| null | Biller's transaction reference — set once `COMPLETED` |
| `refund` | object \| null | Return of the LKR to your float after a biller failure (see [Refunds](#refunds)) |
| `paidAt` | string | ISO 8601 timestamp when CeyPay debited your float |
| `completedAt` | string \| null | ISO 8601 timestamp when the biller confirmed payment |
| `createdAt` | string | ISO 8601 timestamp when the bill payment was created |

### Error Responses

| Status | Description |
|--------|-------------|
| 400 | Invalid request, `amount` outside the biller's limits, or `provider` sent |
| 404 | Unknown biller |
| 409 | `merchantTradeNo` already used |
| 422 | Insufficient float balance, or `Idempotency-Key` reused with a different request body |
| 503 | Bill payments temporarily unavailable |

A rejected request never debits your float, and no bill payment is created.

### Idempotency

Send an `Idempotency-Key` header to retry a create request safely:

- **Same key, same body**: CeyPay returns the original bill payment without debiting your float again.
- **Same key, different body**: CeyPay rejects the request with `422`.

Use a stable value such as your internal transaction ID. `merchantTradeNo` also prevents duplicates, but a repeated `merchantTradeNo` returns `409` instead of the original bill payment.

## Get Bill Payment

Returns a single bill payment. Use it to poll status.

```
GET /v1/bill/payment/:id
```

### Path Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `id` | string (UUID) | `billPaymentId` from Create Bill Payment |

### Example Request

```bash

  -H "x-api-key: ak_live_abc123" \
  -H "x-timestamp: 1762934400000" \
  -H "x-signature: your_signature_here"
```

```json
  "merchantTradeNo": "BILL-77120",

  "biller": {
    "code": "CEBB",
    "name": "Ceylon Electricity Board (CEB)",

  "accountNumber": "1234567890",
  "amountLkr": 4850,
  "amountUsdt": null,
  "payProvider": null,
```

## Bill Payment Status

| Status | Description |
|--------|-------------|
| `PROCESSING` | CeyPay debited your float and is paying the biller |
| `COMPLETED` | Biller confirmed the payment — `reference` and `completedAt` are set |
| `FAILED` | Biller rejected the payment. CeyPay returns the LKR to your float |

```
PROCESSING → COMPLETED
     │
     └→ FAILED (LKR returned to your float)
```

## Refunds

If the biller rejects the payment, the status moves to `FAILED` and CeyPay returns the full amount to your float automatically. The `refund` object shows the return:

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | `COMPLETED` once the LKR is back on your float |
| `completedAt` | string \| null | ISO 8601 timestamp when the LKR returned to your float |
| `failedAt` | string \| null | Always `null` for float refunds |

`refund` stays `null` until the LKR is back on your float. CeyPay retries a delayed return automatically, so a `FAILED` bill with `refund: null` resolves without action from you.

### Float Movements

Each bill payment appears in your [Float Balance Ledger Report](/api/v1/offramp#float-balance-ledger-report) with its `billPaymentId`:

- **`DEBIT`** when you create the bill payment
- **`REFUND`** if the biller fails it — the full amount returns to your float

## Webhooks

Set `webhookUrl` when you create a bill payment to receive `bill.status_changed` events. CeyPay sends one when the bill payment reaches a final status: `COMPLETED` or `FAILED`.

### Payload

```json
{
  "event": "bill.status_changed",
  "billPaymentId": "8a2b3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
  "merchantTradeNo": "BILL-77120",
  "status": "COMPLETED",
  "billerCode": "CEBB",
  "accountNumber": "1234567890",
  "amountLkr": 4850,
  "reference": "CEB-884213",
  "refund": null,
  "timestamp": "2026-11-12T10:00:31.000Z"
}
```

### Payload Fields

| Field | Type | Description |
|-------|------|-------------|
| `event` | string | Always `bill.status_changed` |
| `billPaymentId` | string (UUID) | CeyPay bill payment ID |
| `merchantTradeNo` | string \| null | Your reference |
| `status` | string | Current status (see [Bill Payment Status](#bill-payment-status)) |
| `billerCode` | string | Biller code |
| `accountNumber` | string | Account paid |
| `amountLkr` | number | LKR amount |
| `reference` | string \| null | Biller's transaction reference — set when `COMPLETED` |
| `refund` | object \| null | Return of the LKR to your float (see [Refunds](#refunds)) |
| `timestamp` | string | ISO 8601 timestamp when CeyPay sent the event |

A failed bill payment normally produces a single `FAILED` webhook, sent after CeyPay returns the LKR to your float, so `refund.status` is already `COMPLETED`. If the return is delayed, you first receive `FAILED` with `refund: null`, then a second `FAILED` webhook with `refund.status: COMPLETED` once the LKR is back.

Bill webhooks use the same ED25519 signature headers and retry policy as payment webhooks. See [Webhooks](/api/v1/webhooks) for signature verification and retries.

## Error Responses

| Status | Error | Description |
|--------|-------|-------------|
| 400 | Bad Request | Validation error, invalid account number, amount outside the biller's limits, or `provider` sent |
| 401 | Unauthorized | Invalid API key, timestamp, or HMAC signature |
| 403 | Forbidden | Account inactive, or bill payments not enabled |
| 404 | Not Found | Unknown biller, account not found, or bill payment not found |
| 409 | Conflict | `merchantTradeNo` already used |
| 422 | Unprocessable Entity | Insufficient float balance, or `Idempotency-Key` reused with a different request body |
| 429 | Too Many Requests | Rate limit exceeded |
| 503 | Service Unavailable | Bill payments temporarily unavailable |

See [Error Codes](/api/v1/errors) for detailed error handling.
